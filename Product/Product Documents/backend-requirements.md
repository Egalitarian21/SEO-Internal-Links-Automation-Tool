HTML，抽取正文、标题、H1-H3、canonical、noindex||已有内链抽取|解析正文中的站内链接（source / target / anchor / paragraph）||页面画像生成|LLM 生成 L0（一句话定位）+ L1（结构化画像）||候选召回|基于主题簇 + 实体 + 业务优先级召回候选目标页||确定性规则过滤|排除已链接、noindex、分页页、出链超限等||LLM 推荐生成|仅对 Top-N 候选执行 L2 精读，输出锚文本、目标 URL、插入位置||推荐执行清单|输出 `锚文本 / 目标链接 URL / 博客原文对应插入位置` 三字段||审核记录|采纳 / 拒绝 / 修改后采纳，记录审核结果||CSV 导出|推荐清单导出 CSV 供 SEO 工程师执行|### 1.2 MVP 外（后置）* ❌ Shopify API 直写（阶段 5）* ❌ 向量检索 + Embedding（阶段 2 视需引入）* ❌ 自动主题簇聚类（MVP 用人工标注 + 规则）* ❌ Lint 健康检查（阶段 4）* ❌ 规则候选自动生成（阶段 3）* ❌ 异步任务队列 Celery（MVP 用 APScheduler 后台线程）* ❌ 用户认证（内部工具暂不需要）* ❌ 效果追踪 Dashboard（阶段 6）### 1.3 设计原则1. **先确定性规则，再 LLM 判断**：能用 SQL / 正则解决的不调用 LLM2. **L0/L1 常驻，L2 按需**：L2 全文只在 Top-3 候选时加载，控制 token 成本3. **人工审核优先**：所有推荐进入审核队列，人工确认后才生效4. **Markdown + SQLite 双层**：Markdown 负责可读知识沉淀，SQLite 负责结构化查询5. **可回溯**：所有 LLM 调用记录 prompt + response + 推荐轨迹\---## 2\. 技术栈与运行环境|层|选型|版本要求||-|-|-||编程语言|Python|3.11+||Web 框架|FastAPI|≥ 0.110||ASGI Importer（导入服务）**职责**：接收 URL 列表 / sitemap.xml，去重后入 `pages` 表（status='pending'），创建 `import\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_tasks` 记录。**接口契约**：```pythonclass Importer:    async def import\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_url\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_list(urls: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[str]) -> ImportTaskResult: ...    async def import\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_sitemap(sitemap\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_url: str) -> ImportTaskResult: ...class ImportTaskResult(BaseModel):    task\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_id: int    total: int    new: int    duplicates: int```**关键规则**：* URL 必须经过 `url\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_utils.normalize()`（Shopify canonical：`/collections/\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\*/products/X` → `/products/X`）* 重复 URL 跳过，不报错* sitemap.xml 解析支持嵌套 `<sitemapindex>`\---### 6.2 Crawler（页面抓取）**职责**：拉取 `status='pending'` 的页面 HTML，保存到 `raw/pages/{slug}.html`，更新 `pages.raw\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_html\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_path` 和 `last\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_crawled\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_at`。**接口契约**：```pythonclass Crawler:    async def crawl\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_page(page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_id: int) -> CrawlResult: ...    async def crawl\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_batch(page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_ids: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[int], concurrency: int = 5) -> BatchCrawlResult: ...```**关键规则**：* 使用 `httpx.AsyncClient`，超时 30s* User-Agent 可配置* 并发上限默认 5（可配置 `CRAWLER\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_MAX\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_CONCURRENCY`）* 失败重试 3 次（指数退避：1s → 4s → 16s）* HTTP 200 才视为成功，4xx/5xx 标记 `status='failed'`，记录 `error\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_message`\---### 6.3 Cleaner（内容清洗）**职责**：从原始 HTML 抽取正文 + 元数据，输出结构化对象。**接口契约**：```pythonclass Cleaner:    def clean(html: str, url: str) -> CleanedPage: ...class CleanedPage(BaseModel):    title: str | None    canonical\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_url: str | None    is\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_indexable: bool                    # 检测 <meta name="robots" content="noindex">    body\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_text: str                        # 纯文本正文    body\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_html: str                        # 清洗后的正文 HTML（保留 <p>, <h1-6>, <a>）    headings: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[Heading]               # \\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[{level, text, anchor\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_id}]    paragraphs: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[Paragraph]           # \\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[{index, text, html, has\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_link, is\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_first}]    page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_type\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_hint: str | None            # 从 URL 推断：blog/collection/product```**关键规则**：* 主用 `trafilatura.extract`，HTML 结构提取用 BeautifulSoup* 保留段落级结构（用于后续插入位置定位）* 移除 `<script>`, `<style>`, `<nav>`, `<footer>`, 广告类 div* 第一个段落标记 `is\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_first=True`（规范要求首段不插链）\---### 6.4 LinkExtractor（已有内链抽取）**职责**：从清洗后的 HTML 中抽取所有 `<a href>` 链接，写入 `links` 表。**接口契约**：```pythonclass LinkExtractor:    def extract(page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_id: int, body\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_html: str, source\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_url: str) -> list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[Link]: ...```**字段约束**：* `is\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_internal`：基于 URL 域名判断（同 host）* `paragraph`：锚文本所在段落的纯文本（截断 500 字符）* 跳过导航/页脚区域的链接（Cleaner 已移除）\---### 6.5 Profiler（页面画像生成）**职责**：调用 LLM 为单页生成 L0 + L1 画像，写入 `page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_profiles` 表 + `wiki/pages/{slug}.md`。**接口契约**：```pythonclass Profiler:    async def PageProfile(BaseModel):    l0\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_summary: str                       # ≤ 60 字符    parent\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_topic: str    core\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_entities: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[str]              # 3-8 个    suggested\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_anchors: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[str]          # 3-10 个，必须从原文出现    target\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_priority: int                  # 1-5    link\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_strategy: recall\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_candidates(source\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_url: str, top\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_k: int = 30) -> list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[CandidatePage]: ...class CandidatePage(BaseModel):    page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_id: int    url: str    page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_type: str    title: str    l0\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_summary: str    recall\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_reason: str                    # "topic\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_match" / "entity\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_overlap" / "business\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_priority"    recall\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_score: float```**召回策略（多路 + 合并）**：```路 1：同主题召回（SQL）  WHERE pp.parent\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_topic = source.parent\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_topic AND p.url != source\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_url路 2：实体重叠召回  解析 source 的 core\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_entities，找其他页 core\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_entities 与其有交集的页  实现：Python 端 Jaccard 相似度（MVP 阶段数据量小够用）路 3：业务优先级召回  WHERE pp.target\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_priority >= 4 AND p.page\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_type IN ('collection','product')合并：按 recall\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_score 降序，去重，取 top\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_krecall\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_score = topic\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_match \\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\* 0.5 + entity\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_jaccard \\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\* 0.3 + business\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_priority/5 \\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\* 0.2```**MVP 实现说明**：* 不引入 embedding，纯 SQL + JSON 字段处理* 主题匹配用精确字符串（后续可改为 LLM 标签归一化）\---### 6.7 FilterEngine（确定性规则过滤）**职责**：对召回的候选页应用确定性规则，过滤掉不应推荐的目标。**接口契约**：```pythonclass FilterEngine:    def filter(source\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\_url: str, candidates: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[CandidatePage]) -> FilterResult: ...class FilterResult(BaseModel):    passed: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[CandidatePage]    filtered: list\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[FilteredCandidate]     # \\\\\\\\\\\\\\\\\\\\\\\\\\\\\\\[{page,
